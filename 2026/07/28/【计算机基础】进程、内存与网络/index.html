【计算机基础】进程、内存与网络

|总字数:1.8k|阅读时长:5分钟|浏览量:

一、进程与线程

进程和线程的区别？

  1. 进程是运行时的程序，是系统进行资源分配和调度的基本单位，它实现了系统的并发。
  2. 线程是进程的子单位，也称为轻量级进程，它是 CPU 进行分配和调度的基本单位，也是独立运行的基本单位，实现了进程内部的并发。
  3. 一个程序至少拥有一个进程，一个进程至少拥有一个线程，线程依赖于进程而存在。
  4. 进程拥有独立的内存空间，而线程共享进程的内存空间，自己不占用资源。
  5. 线程的优势：线程之间的信息共享和通讯比较方便，不需要资源的切换。

多核处理器如何做到并发执行几百个线程？

其实并不是 CPU 真的同时处理了几百个线程，可以从四个方面理解：

  • 多核 CPU：比如四核 CPU，是真的能并行执行四个线程的。
  • 超线程技术：一个物理核心模拟两个逻辑核心，两个线程之间共享资源，提高资源利用率。
  • 时间片轮转：给每个线程一个时间片（大概几毫秒），CPU 快速切换执行，速度很快，人类基本观察不到。

二、死锁

什么是死锁？ 多个进程并发执行，各自占有一定资源的情况下，都希望获得其他进程占有的资源以推进执行，但其他进程同样期待获得对方的资源，大家都不愿意释放自己的资源，从而导致相互阻塞、循环等待、进程无法推进的情况。

死锁的四个必要条件：

  1. 互斥条件：一个资源每次只能被一个进程使用。
  2. 请求并保持条件：因请求资源而阻塞时，对已获得的资源保持不放。
  3. 不剥夺条件：在未使用完之前不能被剥夺，只能自己释放。
  4. 循环等待：若干进程之间形成头尾相接的循环等待资源关系。

死锁的处理：

  1. 死锁预防：打破四个死锁条件之一。
  2. 死锁避免：使用算法进行资源分配，防止系统进入不安全状态，如银行家算法。
  3. 死锁检测和解除：抢占资源或者终止进程。

银行家算法是最有代表性的避免死锁的算法。它允许进程动态申请资源，但系统在分配前会先计算此次分配的安全性——若分配不会导致系统进入不安全状态则分配，否则等待。所谓「安全状态」指存在一个进程序列 {P1, P2, … Pn}，对于每个进程 Pi，它以后尚需的资源不大于当前资源剩余量与其余进程所占资源量之和。

三、内存管理与虚拟内存

操作系统如何管理内存？什么是虚拟内存？

操作系统通过分页管理机制进行内存管理：将程序的逻辑地址划分为固定大小的页，物理内存划分为同样大小的帧。程序加载时，可以将任意一页放入内存中任意一个帧，这些帧不必连续，从而实现了离散分配。

虚拟内存基于分页存储管理机制，它允许程序不必将所有页都放入内存，而只将一部分页映射到内存，另一部分放在外存（磁盘等）。当引用到不在内存中的页时，系统产生缺页中断，从外存调入该页，从而产生一种「逻辑上内存被扩充」的感觉——实际上物理内存并没有增大。

LRU（最近最少使用）：选择最近最长时间未被访问过的页面予以淘汰。它认为过去一段时间未访问的页面，在最近的将来也不会被访问。LRU 算法性能较好，但需要寄存器和栈的硬件支持。

四、缓存

什么是缓存（Cache）？为什么需要缓存？

  1. Cache 即 CPU 的高速缓冲存储器，用于减少处理器访问内存所需的平均时间。
  2. 由于 CPU 的计算速度远远大于从内存取数据的速度，如果每次都让 CPU 去内存取数据，会浪费 CPU 的计算能力。所以设计了缓存，CPU 通过读写缓存来获取操作数，结果也通过缓存写入内存。

如何提高缓存命中率？

  • 注意程序的局部性原理，遍历数组时按照内存顺序访问。
  • 充分利用 CPU 的分支预测功能，将预测的指令放到缓存中执行。
  • 缓存的容量和块长是影响缓存效率的重要因素。

缓存并不是最快的存储部件——寄存器比缓存更快。

五、编译链接

从 C++ 源文件到可执行文件的过程？ 包括四个阶段：

  1. 预处理阶段：处理头文件包含关系，对预编译命令进行替换，生成预编译文件。
  2. 编译阶段：将预编译文件进行词法分析、语法分析、语义分析及优化后，生成汇编代码。
  3. 汇编阶段：将汇编文件转换成机器码，生成可重定位目标文件（.obj）。每一条汇编语句几乎都对应一条机器指令，根据对照表一一翻译即可。
  4. 链接阶段：将多个目标文件和所需的库连接成可执行文件（.exe）。

六、计算机网络

OSI 七层架构、TCP/IP 五层架构是网络的基础模型。

TCP 和 UDP 的区别

  1. TCP 是传输控制协议，UDP 是用户数据报协议。
  2. TCP 是面向连接的、可靠的数据传输协议，要通过三次握手建立连接；UDP 是无连接的、不可靠的数据传输协议，采取尽力而为的策略，不保证接收方一定能收到正确数据。
  3. TCP 面向字节流，UDP 面向数据报。
  4. TCP 只支持点对点，UDP 支持一对一、一对多和多对多。
  5. TCP 有拥塞控制机制，UDP 没有。

补充特性：

  • UDP：无连接，单包大小控制在 64K 以内，不可靠传输，由于不需要连接速度稍快。
  • TCP：面向字节流的可靠传输，需要三次握手 / 四次挥手来建立、断开连接，因此传输效率较慢。

HTTP 与 Socket

  • HTTP 是一种应用层协议，用来让客户端和服务器传递数据。特点是每次请求完就断开，请求和响应都是文本格式（如 JSON），本质上是通过 TCP 来发送的。
  • Socket（套接字） 是一种通信机制，是操作系统提供的网络「插口」，让程序可以进行网络通信。它更底层、更通用——HTTP 本质上就是通过 Socket 实现的。Socket 本质是包含了 TCP/IP 协议的 API，进行网络开发时都要使用它。

七、其他

如何判断链表是否有环？

快慢指针法：快指针每次走两步，慢指针每次走一步。当快指针等于慢指针时，说明链表有环。
