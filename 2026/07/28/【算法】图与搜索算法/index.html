【算法】图与搜索算法

一、A* 算法

A* 算法是一种启发式搜索算法，常用于游戏中的路径寻找。它是在 Dijkstra 算法的基础上加入启发函数的一种改进，兼顾了路径最短和搜索效率。

  • g(n)：从起点到当前节点 n 的实际代价（路径长度）
  • h(n)：从当前节点 n 到目标节点的启发式估计代价（通常用欧几里得距离或曼哈顿距离）

每次从开放列表（Open List）中选取 f(n) 最小的节点进行扩展，直到找到目标点。

优化思路：

  • 如果地图是静态的，可以进行预处理，加入导航节点。
  • 对于大地图，可以使用分区寻路：先在粗略地图（低分辨率）上规划大概路径，再在细节地图（高分辨率）上精确规划每一小段。
  • Unity 中可借助 NavMesh 来代替手写 A*，在复杂场景中更高效。

二、JPS 跳点搜索

JPS（Jump Point Search）算法实际上是对 A* 寻路算法的一个改进，改进点在于扩展搜索节点时提出了更优化的策略。

A* 在扩展节点时会把节点的所有邻居都考虑进去，这样 Open List 中点的数量会很多，搜索效率较慢。JPS 算法通过寻找跳点的方式，排除了大量不感兴趣的点，减少了 Open List 中搜索点的数量，速度大大提高。

三、广度优先与深度优先遍历

  • 广度优先遍历（BFS）：借助队列逐层向外扩展，先访问离起点近的节点。常用于求无权图的最短路径。
  • 深度优先遍历（DFS）：借助栈（或递归）一路走到底，再回溯。常用于连通性判断、拓扑排序等场景。

四、噪声算法

柏林噪声（Perlin Noise） 是一种梯度噪声，能生成看起来自然、连续的随机值，广泛用于地形高度图生成、云雾、水面波动等程序化内容。相比纯随机数，它的相邻采样值之间是平滑过渡的，因此不会产生突兀的噪点。

五、行为树 vs 状态机

游戏 AI 决策的两大主流方案。

特性 状态机（FSM） 行为树（BT）
设计 事件驱动状态跃迁（如「发现玩家 → 追击」） 条件驱动节点执行（树状分层决策）
结构 状态集合 + 转移条件 节点组合（控制节点、装饰节点、任务节点）
复杂度管理 状态数量↑ → 转移条件指数级增长（N×(N-1)），易「状态爆炸」 节点复用性强，子树模块化，适合复杂逻辑
执行逻辑 线性跳转，当前状态唯一 自顶向下遍历，节点返回 Success/Failure/Running

实现方式与性能

1. 状态机（FSM）

  • 常用方法：枚举 + switch-case；状态类（IState 接口 + OnEnter/Update/Exit）。
  • 优化点：避免频繁状态切换；使用字典注册状态减少 GC。
  • 性能：执行效率高（直接跳转），内存占用低。

2. 行为树（BT）

  • 节点类型：Selector（或逻辑）、Sequence（与逻辑）、Decorator（条件修饰）、Action（具体行为）。
  • 工具支持：Behavior Designer（可视化编辑）、NodeCanvas；也可通过 BehaviorNode 基类派生自定义节点。
  • 性能瓶颈：高频 Tick 遍历可能消耗 CPU，需要优化（如降低非实时节点的更新频率）。

适用场景与选择

  • 状态机适合状态较少、逻辑清晰的角色（如简单的巡逻/追击/攻击切换）。
  • 行为树适合逻辑复杂、需要模块化复用的 AI（如带有多层决策的 Boss）。

实际项目中两者也常结合使用：用行为树做高层决策，用状态机管理具体动作的执行。
