【C++】STL与容器底层

发表于2026-07-28|更新于2026-10-13|技术笔记C++
|总字数:1.4k|阅读时长:4分钟|浏览量:

一、STL 的六大部件

STL 的精髓在于「算法与数据结构的分离」，通过迭代器实现统一接口。

  1. 容器（Containers）：存放数据的各种数据结构，如 vector、list、set、map。
  2. 算法（Algorithms）：常用算法，如 sort、search 等。
  3. 迭代器（Iterators）：作用相当于「指针」，用来在容器中遍历元素。不同容器提供不同类别的迭代器（输入、输出、前向、双向、随机访问），把算法和容器解耦。
  4. 仿函数（Functors）：行为类似函数，为算法提供某种策略。本质是重载了 operator() 的类对象，可以像函数一样使用，如 std::greater<int>()。后来也常被 Lambda 替代。
  5. 适配器（Adapters）：用来修饰容器、仿函数或迭代器接口，如 queue、stack，内部其实都借助 deque 实现。
  6. 分配器（Allocators）：管理内存分配与释放。STL 默认用 std::allocator，也可自定义，是容器的模板参数之一。

二、各容器的底层实现

vector：底层是一块连续内存的数组，核心在于长度自动可变。它由三个迭代器（指针）维护：指向首元素的 start、指向尾元素的 finish、指向内存末端的 end_of_storage。扩容机制是：当可用空间不足时，分配当前空间的两倍或「当前空间 + 所需新空间」（取较大值），扩容必须经过「重新配置、元素移动、释放原空间」等过程。

list：底层是一个循环双向链表，链表结点和链表分开独立定义。结点包含 prev、next 指针和 data 数据。

deque：双向队列，由分段连续空间构成，每段连续空间是一个缓冲区，由一个中控器（map 指针）控制。它维护 start 和 finish 两个迭代器，指向第一个和最后一个缓冲区，可以在前端或后端扩容。

stack 和 queue：栈和队列，都由 deque 作为底层容器实现，属于容器配接器——修改了 deque 的接口。stack 封住 deque 的头端开口（先进后出），queue 封住尾端开口（先进先出）。二者也可以用 list 作为底层实现。

priority_queue：优先队列，以 vector 作为底层容器，以 heap 作为处理规则。heap 的本质是一个完全二叉树。

set 和 map：底层都由红黑树实现。红黑树是一种二叉搜索树，但多了一个颜色属性，性质如下：

  1. 每个结点非红即黑；
  2. 根节点是黑的；
  3. 如果一个结点是红色的，那么它的子节点是黑色的；
  4. 任一结点到树尾端（NULL）的路径上含有的黑色结点个数必须相同。

通过以上限制，红黑树确保没有一条路径会比其他路径长出两倍以上，因此是一种弱平衡二叉树。相对于严格平衡的 AVL 树，它的旋转次数少，所以在插入、删除操作较多的情况下通常使用红黑树。

三、时间复杂度对比

容器 随机访问 查找 插入/删除 备注
vector O(1) 无序 O(n) / 有序 O(logn) 尾部最快，头部最慢 二倍扩容可能浪费内存
list 不支持 O(n) O(1)（调整指针） 占用内存小
deque 支持（比 vector 慢） O(n) 两端 O(1)，中间慢 支持双端扩容
set/map —— O(logn) O(logn) 红黑树实现，内存小
unordered_set/map —— O(1)（最差 O(n)） O(1)（最差 O(n)） 哈希表实现，无序

几点说明：

  • vector 占用内存较大，二倍扩容机制可能导致内存浪费，内存不足时扩容的拷贝也会造成较大性能开销。
  • list 不支持随机访问，只能扫描查找，但插入删除只需调整指针；不会造成内存浪费。
  • unordered 系列 底层基于哈希表，理论增删查改 O(1)，但数据分布是否均匀会极大影响性能。

四、常见面试点

push_back 与 emplace_back 的区别

  • emplace_back：使用传递来的参数直接在容器管理的内存空间中构造元素（只调用构造函数）。
  • push_back：会先创建一个局部临时对象，再将其压入容器（可能调用拷贝构造或移动构造函数）。

所以 emplace_back 通常更高效，省去了临时对象的构造与拷贝/移动。

STL 的排序用了哪种算法

C++ 的 sort 综合使用了快速排序、插入排序和堆排序：数据量大时用快排，划分区段较小时用插入排序，当划分有导致最坏情况的倾向时切换为堆排序。

AVL 树与红黑树的区别

  • AVL 树是高度平衡的，频繁的插入和删除会引起频繁的 rebalance（旋转），导致效率下降。
  • 红黑树不是高度平衡的，算是一种折中：插入最多两次旋转，删除最多三次旋转。因此在插入、删除频繁的场景下，红黑树表现更好。

五、哈希表补充

哈希表的长度为什么要是质数？ 使用质数可以降低发生冲突的概率，使哈希后的数据更加均匀。如果使用合数，可能导致很多数据集中分布到一个点上，造成冲突。

如何处理冲突？ 常见方法有开放定址法（线性探测、平方探测）和拉链法。

哈希表怎么删除元素？ 线性探测法并不会真正删除一个元素，而是做一个标记，否则可能导致正常的查找出错。
