【AI探索】给技术博客做一套自动化封面生成系统

为什么自己生成封面

博客文章涉及内存管理、垃圾回收、排序和网络同步等抽象主题。图库照片往往只能提供泛化的电脑或代码画面，很难说明文章具体讲什么。现在我用 SVG 根据文章标题和分类排版标题，并绘制对应的技术示意图，让封面在保持统一的同时更贴近文章主题。

当前视觉与版式

封面采用浅灰绿纸面、深色标题，以青绿为主色、暖橙作少量强调。完整封面为 1200 × 630：左侧放分类、标题和主题说明，右侧展示技术图解。列表缩略图为 600 × 360，只保留图解，不重复封面标题，缩小后也能看清内容。

生成器会先写出完整封面的 SVG，再调用本机 Chrome、Chromium 或 Edge 渲染 PNG；缩略图则保留为 SVG。中文字体和线条由浏览器直接绘制，不需要额外的图像处理库。

标题和分类如何决定图解

脚本读取文章 front matter 中的标题和分类，按分类分支和标题关键词选择预先编写的 SVG 图解。它不读取正文，也不自动总结文章内容；图解旁的简短说明是代码中为主题预先设置的文案。

文章主题 图解示例
C++ / C# 栈与堆、虚函数分派、资源所有权、参数传递
Unity 生命周期、动画、资源管理、GC、渲染
网络 数据传输、帧同步、状态同步
算法与数据结构 排序、图搜索、哈希处理
AI Coding 任务、代码代理、代码库与人工复核的协作流程
AI Agent 目标、规划、工具调用与反馈的节点图
项目实战 模块架构或哈夫曼树

选图依赖规则而非正文理解。同一分类下的文章如果选择了相同主题图解，示意内容也可能相同；当前不保证每篇文章都有独一份的图。

从文章到页面图片

  1. 运行生成脚本，读取没有封面字段的新文章，生成完整封面 SVG 和图解缩略图，并将完整 PNG 路径写入 front matter。
  2. SVG 转 PNG 脚本只渲染完整封面；已有且比 SVG 更新的 PNG 会跳过。
  3. 构建 Hexo 时，scripts/cover-thumbnails.js 会将页面中指向自动封面 PNG 的图片替换为对应缩略图。分享元数据和封面原图仍使用 PNG。

改过图解或版式后，重新生成所有程序封面：

已有 cover: 的文章默认跳过。--all 只覆盖路径位于 /img/covers/gen/ 的自动封面；其他路径的手动封面（例如项目实景截图）会保留。Python 生成器和 shell 包装脚本位于 tools/covers/；scripts/ 目录只保留 Hexo 插件，避免 Hexo 把 Python 和 shell 文件误当作 JavaScript 加载。图片在本地生成并提交，GitHub Actions 负责构建和部署。

这套规则生成速度快、风格稳定，也不需要 AI 图片服务；代价是它只依据标题和分类选择模板，不理解正文。同一主题下可能复用图解，这是当前方案的限制。

小结

这套流程让封面风格统一、示意图贴近主题，并为列表单独生成清晰的小图；项目实景截图仍可手动指定。新增主题时，需要在 tools/covers/gen_covers.py 中补上选择规则和对应图解。
