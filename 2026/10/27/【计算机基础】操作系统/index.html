第一章 操作系统概述与硬件运行机制

1.1 操作系统的四大基本特征与内核架构

  1. 操作系统的四大基本特征
    • 并发（Concurrency，最核心特征）：
      • 并发 vs 并行（必考辨析）：并发是指两个或多个事件在同一时间间隔（宏观上同时、微观上分时交替）内发生（单核 CPU 即可支持并发）；并行（Parallelism）是指两个或多个事件在同一时刻（微观上真正同时）发生（必须具备多核 CPU 硬件）。
    • 共享（Sharing）：系统中的资源可供内存中多个并发执行的进程共同使用，分为两种方式：
      1. 互斥共享（如打印机、互斥锁、临界资源）：在一段时间内只允许一个进程访问；
      2. 同时访问（如磁盘文件、可重入代码）：宏观上多个进程同时访问，微观上交替分时读写。
      • 并发与共享互为存在条件：没有并发就谈不上资源共享；若不能有效管理资源共享，并发执行也无法实现。
    • 虚拟（Virtualization）：把一个物理实体变为若干个逻辑上的对应物：
      • 时分复用技术（如虚拟处理器：多进程分时复用单颗物理 CPU）；
      • 空分复用技术（如虚拟存储器：利用磁盘空间扩展物理内存，为每个进程提供独立的 4GB / 64 位虚拟地址空间）。
    • 异步（Asynchronism）：并发进程以不可预知的、走走停停的相对速度向前推进，但操作系统必须保证只要运行环境相同，多次运行的最终结果完全相同（可再现性）。
  2. 宏内核（大内核）与微内核架构对比
    • 宏内核（Monolithic Kernel，如 Linux、UNIX）：将进程管理、内存管理、文件系统、网络协议栈、设备驱动程序全部编译在同一个内核地址空间中运行。优点：各模块间直接函数调用，性能极高；缺点：内核庞大，任一驱动崩溃可能导致整个内核崩溃。
    • 微内核（Microkernel，如 Mach、鸿蒙 HarmonyOS 微内核）：内核态仅保留最核心的中断处理、进程/线程调度与进程间通信（IPC），而将文件系统、设备驱动、网络协议栈全部移至用户态作为独立服务进程运行。优点：可靠性、安全性与可扩展性极高；缺点：用户态服务之间必须频繁通过内核 IPC 消息传递通信，导致频繁的用户态/内核态上下文切换开销，性能略低。

1.2 CPU 运行模式、中断与系统调用

  1. 处理器双模式（用户态 vs 内核态）与两类指令
    • 为什么要区分用户态与内核态：防止用户应用程序有意或无意地破坏操作系统内核代码、篡改其他进程内存或独占硬件外设。硬件通过程序状态字寄存器（PSW）中的模式位来标识当前特权级：
      • 用户态（目态，User Mode，x86 Ring 3）：CPU 只能执行非特权指令（算术运算、访存用户空间、普通跳转），严禁执行特权指令。
      • 内核态（管态 / 核心态，Kernel Mode，x86 Ring 0）：运行操作系统内核程序，CPU 可以执行指令集中的全部指令（包含特权指令）。
    • 常见特权指令（在用户态下执行必触发硬件异常）：I/O 输入输出指令、置时钟指令、开/关中断指令（STI / CLI）、清内存指令、修改页表基址寄存器（CR3）与修改程序状态字（PSW）指令。
  2. 中断（Interrupt）与异常（Exception）分类体系 中断与异常是 CPU 由“用户态”进入“内核态”的唯一途径（而由“内核态”返回“用户态”则是通过执行特权指令 iret 中断返回指令恢复用户态 PSW 实现）：

分类 触发源与同步/异步属性 子类与典型案例 处理完毕后的返回断点地址
1. 外中断
(Interrupt)		 来自 CPU 外部硬件设备的信号，与当前正在执行的指令无关（异步事件） • 可屏蔽中断：通过 INTR 引脚进入，受关中断标志控制（如时钟中断、网卡收包、磁盘 I/O 完成）
• 不可屏蔽中断：通过 NMI 引脚进入，不可屏蔽（如电源掉电、内存奇偶校验错）		 固定返回到被中断指令的下一条指令继续执行
2. 内中断 / 异常
(Exception)		 来自 CPU 内部，由当前正在执行的指令直接引发（同步事件，不可屏蔽） • 自陷 / 陷入 (Trap)：程序预先有意安排的主动陷入（如系统调用 syscall / int 0x80、调试断点）
• 故障 (Fault)：由错误条件引起但可被内核修复（如缺页异常 Page Fault、除数为 0）
• 终止 (Abort)：致命硬件或内核错误，无法恢复		 • Trap：返回到下一条指令
• Fault（如缺页）：修复后返回到引发故障的当前指令重新执行
• Abort：不返回，直接终止进程
  1. 中断处理与系统调用（System Call）全流程
    • 中断响应中“硬件自动完成”与“软件内核完成”的分工边界（必考）：
      1. 由 CPU 硬件（中断隐指令）自动完成的三件事：① 关中断（防止保护现场中途被打断）；② 保存断点（将当前程序计数器 PC 和程序状态字 PSW 压入内核栈）；③ 引出中断服务程序（根据中断向量号查中断向量表，将对应服务程序入口装入 PC，并切换 PSW 为内核态）。
      2. 由操作系统中断服务程序（软件）完成的事：① 保护通用寄存器现场与屏蔽字；② 开中断（若允许嵌套中断）；③ 执行具体中断处理逻辑；④ 关中断、恢复通用寄存器现场；⑤ 执行 iret 指令恢复 PC 和 PSW 返回用户态。
    • 系统调用过程：用户程序将系统调用号放入指定寄存器（如 eax / rax），执行陷入指令（syscall / sysenter / int 0x80，注意陷入指令本身是唯一能在用户态执行的非特权指令）主动触发内中断进入内核态，内核根据系统调用表分派执行对应内核函数，完成后返回用户态。

第二章 进程与线程、CPU 调度、同步互斥与死锁

2.1 进程与线程的本质对比

  1. 进程（Process）的组成与 PCB
    • 定义：进程是程序的一次动态执行过程，是操作系统进行资源分配（内存、文件、设备）和保护的独立基本单位。
    • 进程的组成（进程实体 / 进程映像）：由 PCB（进程控制块）、程序段（代码段）和数据段（含数据、堆、栈）三部分组成。
    • PCB（Process Control Block，Linux 中为 task_struct）：记录进程 PID、状态、优先级、CPU 寄存器现场保护区、页表指针、打开文件描述符表等全部管理信息。PCB 是进程存在的唯一标志（操作系统完全通过感知 PCB 来创建、调度和销毁进程；PCB 常驻内核内存）。
  2. 线程（Thread）的引入与资源共享边界
    • 定义：线程是进程内部的执行流，是操作系统进行 CPU 处理机调度和分派的基本单位（线程自身几乎不拥有系统资源，仅拥有维持独立执行所必需的少量私有上下文）。
    • 同一进程内多个线程的“共享”与“独享”清单（高频必考）：
      • 同进程所有线程共享的资源：进程虚拟地址空间（代码段 .text、全局变量与静态变量 .data/.bss、堆内存 Heap）、打开的文件描述符表（fd）、进程当前工作目录、信号处理函数、定时器与用户 ID。
      • 每个线程私有独享的资源：线程栈（Thread Stack，存放该线程调用链上的局部变量与函数返回地址）、程序计数器（PC）、CPU 通用寄存器集合与状态字、线程 ID（TID）与线程局部存储（TLS）。
    • 为什么进程上下文切换比同进程内线程切换慢得多（底层根因）：
      1. 同一进程内的线程切换共享同一个虚拟地址空间和同一张页表，只需保存/恢复 CPU 寄存器和切换栈指针 RSP；
      2. 而进程切换必须更新页表基址寄存器（x86 CR3）以切换虚拟地址空间，这会强制导致 CPU 的 TLB（地址转换快表）全部失效被冲刷（Flush）；新进程恢复执行后的相当长一段时间内会密集触发 TLB Miss 和 CPU Cache Miss，每次都要重新走多级页表访存，带来高昂的隐性性能惩罚。
  3. 线程的三种实现模型与协程（Coroutine）
    • 用户级线程（ULT，多对一模型）：线程管理完全由用户态线程库实现，内核意识不到线程存在。优点：线程切换无需陷入内核态，开销极小；缺点：一个线程发起阻塞系统调用会导致整个进程的所有线程全部被内核阻塞，且无法利用多核 CPU 并行。
    • 内核级线程（KLT，一对一模型，如 Linux pthread）：每个用户线程直接对应一个内核调度实体。优点：一个线程阻塞不影响其他线程，可真正发挥多核 CPU 并行计算能力；缺点：线程切换需陷入内核态。
    • 协程（有栈/无栈用户态轻量级纤程）：由用户程序自行显式让出（yield）和恢复（resume）的协作式调度执行流，切换仅保存几个寄存器，开销为纳秒级。

2.2 进程状态转换与进程间通信（IPC）

  1. 进程五状态模型与非法转换辨析
    • 五种基本状态：
      1. 创建态（New）：正在分配 PCB 和申请资源；
      2. 就绪态（Ready）：已具备除 CPU 以外的一切运行条件，排在就绪队列中等候调度器指派 CPU；
      3. 运行态（Running）：正在 CPU 上执行（单核 CPU 同一时刻最多只有 1 个进程处于运行态）；
      4. 阻塞态（等待态，Blocked / Waiting）：因等待某个外部事件或非 CPU 资源（如等待磁盘 I/O 完成、等待信号量 P 操作、等待网络收包）而暂停执行；
      5. 终止态（Terminated）：正回收内存资源与撤销 PCB。
    • 状态转换的关键方向属性（必考）：
      • 运行态 → 阻塞态：是进程自身因请求等待某种资源/事件而发起的主动行为；
      • 阻塞态 → 就绪态：是外部等待事件完成（如外设 I/O 中断到来、其他进程执行了 V 操作）后由内核唤醒的被动行为；
      • 两条绝对不可能直接发生的非法转换：就绪态 → 阻塞态（不在 CPU 上运行的就绪进程根本无法执行任何发起等待的指令）、阻塞态 → 运行态（阻塞唤醒后必须先进入就绪队列排队，绝不能跳过就绪态直接抢占 CPU）。

  1. 五种进程间通信（IPC，Inter-Process Communication）机制对比
IPC 方式 底层实现机制 核心特征与适用场景
1. 管道 (Pipe) 内核维护的一块环形内存缓冲区（半双工字节流，读空阻塞、写满阻塞） • 匿名管道 (pipe)：仅限具有亲缘关系的父子/兄弟进程间通信
• 命名管道 (FIFO)：在文件系统中创建路径名，支持任意无亲缘关系进程通信
2. 消息队列 内核空间中保存的消息链表（按消息类型有格式读取） 克服了管道无格式字节流及缓冲区受限的缺点，但仍存在用户态与内核态之间的数据拷贝开销
3. 共享内存
(Shared Memory)		 将同一块物理内存页直接映射到多个进程各自的虚拟地址空间中 所有 IPC 方式中速度最快（进程直接读写内存，零内核拷贝）；但本身不提供任何同步保护，必须配合信号量或互斥锁使用
4. 信号 (Signal) 软件层面的异步事件通知机制（如 SIGINT、SIGKILL(9)、SIGSEGV） 唯一异步通信方式；其中 SIGKILL(9) 和 SIGSTOP(19) 信号不可被捕获、不可被忽略、不可被阻塞
5. 套接字 (Socket) 基于网络协议栈或本地 Unix Domain Socket 既支持本机不同进程通信，又支持跨机器网络进程通信

2.3 处理机（CPU）调度算法与定量指标

  1. 四大定量评价指标公式（必考计算） 设作业 i 的提交（到达）时间为 Ts，开始执行时间为 Tb，完成时间为 Tf，需要运行的服务时间为 Tr：
    • 周转时间 T（从提交到完成的总耗时）：T = 完成时间 Tf - 到达时间 Ts
    • 带权周转时间 W（≥ 1，衡量相对等待感受）：W = 周转时间 T / 实际服务时间 Tr
    • 等待时间 Tw：Tw = 周转时间 T - 实际服务时间 Tr（无 I/O 阻塞时）
    • 响应时间：从用户提交请求到系统首次产生响应（首次获得 CPU）所经历的时间。
  2. 六大经典 CPU 调度算法对比
调度算法 抢占属性 调度准则与核心特性 优缺点与饥饿现象（Starvation）
1. 先来先服务 (FCFS) 非抢占 按到达就绪队列的先后顺序分配 CPU 公平简单；对长作业有利，对短作业极不利（短作业排在长作业后带权周转时间极大）；不会饥饿
2. 短作业/短进程优先
(SJF / SPF / SRTN)		 非抢占 / 抢占 (SRTN) 优先选择估计运行（剩余）时间最短的进程 在所有调度算法中“平均等待时间、平均周转时间”最小（最优）；但对长作业不利，若短作业源源不断到达会导致长作业无限期“饥饿”
3. 高响应比优先
(HRRN)		 非抢占 每次计算响应比并挑最大者：
Rp = (等待时间 + 服务时间) / 服务时间 = 1 + 等待/服务		 综合了 FCFS 与 SJF：等待时间相同时短作业优先；随着长作业等待时间增加其响应比不断增大，彻底克服了长作业饥饿问题
4. 时间片轮转 (RR) 抢占 按 FCFS 排队，每次分配固定时间片 q，用完即剥夺放回队尾 专为分时系统设计，保证良好的响应时间；时间片太大退化为 FCFS，太小则进程频繁切换开销占比过高；不会饥饿
5. 优先级调度 非抢占 / 抢占 按静态或动态优先级选择最高者（系统进程 > 用户进程，I/O 型进程优先级应高于计算型进程） 灵活区分紧急程度；若高优先级进程持续到达，低优先级进程会产生饥饿
6. 多级反馈队列
(MLFQ)		 抢占 设多个优先级从高到低的队列：优先级越高时间片越小；新进程入第 1 级，用完时间片未完成则降入下一级，仅当上级全空才调度下级 集大成者：短作业在第 1 级迅速完成，长批处理作业逐级下沉也能执行，交互作业响应极快（若第 1 级持续涌入新进程仍可能饥饿，可通过定期优先级提升 Aging 解决）

2.4 进程同步、互斥与信号量机制

  1. 临界区（Critical Section）互斥访问的四条准则
    1. 空闲让进：临界区空闲时，应允许一个请求进入的进程立即进入；
    2. 忙则等待：当已有进程进入临界区时，其他试图进入的进程必须等待；
    3. 有限等待：对请求访问的进程，应保证能在有限时间内进入临界区（防止死等/饥饿）；
    4. 让权等待（重要考点）：当进程不能进入临界区时，应立即释放处理器 CPU（转入阻塞态），防止进程在 CPU 上空转“忙等（Busy Waiting）”。
    • 哪些互斥方法不遵循“让权等待”：软件互斥算法（Peterson 算法）、硬件原子指令（TestAndSet、Swap / CAS 实现的自旋锁 Spinlock）以及整型信号量在等待时均在 CPU 上死循环自旋，均不满足让权等待（但自旋锁在多核 CPU 且锁持有时间极短时，可省去线程睡眠与唤醒的上下文切换开销）；只有记录型信号量（互斥锁 Mutex）在获取失败时将进程挂入阻塞队列，满足让权等待。
  2. 记录型信号量（Semaphore）与 PV 原语
    • 信号量结构：包含一个整型变量 S.value（初值代表可用资源数）和一个阻塞等待队列 S.L。
    • P(S) 原语（即 wait(S)，申请资源）：
      1. 执行 S.value--；
      2. 若减 1 后 S.value < 0，说明资源已耗尽（此时 |S.value| 的绝对值恰好等于当前阻塞队列中正在等待该资源的进程个数），调用 block 原语将该进程由运行态转为阻塞态并挂入等待队列 S.L。
    • V(S) 原语（即 signal(S)，释放资源）：
      1. 执行 S.value++；
      2. 若加 1 后 S.value <= 0，说明阻塞队列中仍有进程在等待，调用 wakeup 原语从 S.L 唤醒一个进程由阻塞态转为就绪态。
    • 用信号量实现“互斥”与“前驱同步”的通用公式：
      • 实现临界区互斥：设互斥信号量初值 mutex = 1，进入临界区前 P(mutex)，退出临界区后 V(mutex)（必须成对出现在同一进程中）。
      • 实现前驱同步（语句 A 必须在语句 B 之前执行 A → B）：设同步信号量初值 S = 0，在前驱操作 A 之后执行 V(S)（发出完成信号），在后继操作 B 之前执行 P(S)（等待信号到来，“前 V 后 P”）。

  1. 三大经典同步问题核心模板
    • 生产者-消费者问题（容量为 n 的有界缓冲区）：
      • 信号量设置：互斥信号量 mutex = 1，空缓冲槽同步信号量 empty = n，满缓冲槽（产品）同步信号量 full = 0。
      • 死锁顺序铁律：在同一个进程中，实现同步的 P(empty) 或 P(full) 必须写在实现互斥的 P(mutex) 之前！若颠倒为先 P(mutex) 后 P(empty)，当缓冲区满时生产者拿到 mutex 锁后在 P(empty) 处阻塞睡眠，消费者因拿不到 mutex 锁永远无法消费腾出空位，导致死锁（而两个 V 操作顺序可以任意互换）。
    • 读者-写者问题（允许多个读者同时读，但写者必须与其他读者和写者互斥）：
      • 读优先实现：引入整型计数器 count = 0 记录当前正在读的读者人数，配合互斥锁 mutex = 1（保护 count 变量）和读写大锁 rw = 1：仅第 1 个进入的读者（count == 0）负责执行 P(rw) 加锁阻挡写者，后续读者直接进入；仅最后 1 个离开的读者（--count == 0）负责执行 V(rw) 解锁放行写者。
      • 写优先（读写公平）实现：额外增加一个排队信号量 w = 1，读者在 P(mutex) 前和后、写者在 P(rw) 前和后均包裹一层 P(w) ... V(w)，防止源源不断的读者饿死写者。
    • 哲学家进餐问题（5 个哲学家与 5 根筷子，每个人都先拿左筷子再拿右筷子会导致循环等待死锁）：
      • 三种防死锁方案：① 至多允许 4 名哲学家同时去拿左筷子；② 仅当一名哲学家左右两根筷子同时可用时（用互斥锁包裹同时拿两根筷子的动作）才允许他拿起筷子；③ 奇偶编号错位拿法：奇数号哲学家先拿左筷子再拿右筷子，偶数号哲学家先拿右筷子再拿左筷子（破除循环等待）。

2.5 死锁（Deadlock）的四大条件与银行家算法

  1. 死锁的定义与四大必要条件
    • 定义：多个并发进程因争夺资源而造成的一种互相等待对方手里资源的僵局，若无外力干涉，这些进程都将永远无法向前推进。
    • 产生死锁的四个必要条件（只要死锁发生，这四个条件必定同时成立）：
      1. 互斥条件：进程所申请的资源在一段时间内只能被一个进程排他性独占；
      2. 不剥夺条件（不可抢占）：进程已获得的资源在未使用完之前，不能被其他进程强行剥夺，只能由自己主动释放；
      3. 请求和保持条件（占有并等待）：进程已经保持了至少一个资源，但又提出了新的资源请求，而该新资源已被其他进程占有，此时请求进程阻塞但对自己已获得的资源保持不放；
      4. 循环等待条件：存在一种进程资源的循环等待链 P0 → P1 → ... → Pn → P0。
  2. 死锁的三种处理策略：预防、避免、检测与解除
    • 死锁预防（静态策略：破坏四大必要条件之一）：
      • 破坏互斥条件：如用 SPOOLing 技术将独占打印机改造为共享虚拟设备；
      • 破坏不剥夺条件：请求新资源得不到满足时，必须立即释放自己已持有的全部资源；
      • 破坏请求和保持条件：采用静态一次性分配（AND 型信号量），进程在运行前一次申请完它所需的全部资源；
      • 破坏循环等待条件（工程最常用：顺序资源分配法）：给系统中所有资源类型统一编号，规定任何进程必须严格按照资源编号递增的顺序申请资源（这样持有大号资源的进程绝不会回头去申请小号资源，从数学上彻底消除等待环路）。
    • 死锁避免（动态策略：安全状态与银行家算法）：
      • 安全状态 vs 不安全状态（核心考点）：所谓安全状态，是指系统能按照某种进程推进顺序 <P1, P2, ..., Pn>（称为安全序列）为每个进程分配其所需资源，直至全部进程顺利完成。只要系统处于安全状态，就绝对不会发生死锁；若系统进入不安全状态，则可能发生死锁（注意：不安全状态不一定已经死锁，但死锁状态必定是不安全状态）。
      • 银行家算法（Banker's Algorithm）的四个核心数据结构与手算步骤： 设系统共有 n 个进程、m 类资源：
        1. 最大需求矩阵 Max[n][m]：每个进程对各类资源的最大总需求量；
        2. 已分配矩阵 Allocation[n][m]：当前已经分配给每个进程的资源数；
        3. 最多还需矩阵 Need[n][m]：核心恒等式 Need[i][j] = Max[i][j] - Allocation[i][j]；
        4. 当前可用资源向量 Available[m]。
        • 当进程 Pi 提出资源请求向量 Request_i 时的检验四步： ① 检查 Request_i <= Need[i]（否则报错：申请超出声明的最大需求）； ② 检查 Request_i <= Available（否则 Pi 必须等待：当前系统剩余资源不够）； ③ 试探性分配（修改数值）：Available -= Request_i ， Allocation[i] += Request_i ， Need[i] -= Request_i； ④ 执行安全性检查算法：令工作向量 Work = Available，反复在未完成进程中寻找满足 Need[k] <= Work 的进程 Pk，找到后将其加入安全序列并模拟回收其全部已占资源 Work += Allocation[k]；若全部 n 个进程都能进入安全序列，则正式分配资源，否则作废试分配让 Pi 等待。
    • 死锁检测与解除（资源分配图化简法与死锁定理）：
      • 死锁定理：在资源分配图中，找出一个既不阻塞又非独立的进程节点（其所有请求边都能被当前剩余空闲资源满足），消去它的所有请求边和分配边使其成为孤立点并归还资源；重复此过程，若最终能消去图中所有的边使所有进程节点都成为孤立点，则称该图是“可完全简化的”（无死锁）；反之，不能简化的剩余状态即为死锁。
      • 死锁预防/避免的最小资源数公式（常考秒杀题）：若有 k 个并发进程，每个进程都需要申请 m 个同类资源才能完成任务，则保证系统绝不发生死锁的最少资源总数 R_min 为（让每个人先拿满 m - 1 个，再多加 1 个即可打破僵局）： R_min = k × (m - 1) + 1

第三章 内存管理与虚拟存储器

3.1 进程虚拟地址空间与连续分配管理

  1. 进程虚拟地址空间的经典内存布局（由低地址到高地址）
    • 代码段（.text）与只读常量区（.rodata）：存放程序编译后的机器指令与字符串字面量等只读常量，属性为只读且可被多进程共享。
    • 已初始化数据段（.data）：存放已初始化且初值非 0 的全局变量和静态变量（static）。
    • 未初始化数据段（.bss）：存放未初始化或初值为 0 的全局变量和静态变量（在可执行文件磁盘中不占实际体积，仅记录大小，由加载器在程序启动时统一清零分配）。
    • 堆区（Heap）：由程序员通过 malloc / free 或 new / delete 动态申请与释放，地址由低向高向上增长（↑）。
    • 文件映射与共享库区（mmap）：位于堆与栈之间，用于加载动态链接库（.so / .dll）及内存映射文件（malloc 大块内存如 ≥ 128KB 时底层也直接调用 mmap 分配）。
    • 用户栈区（Stack）：由编译器自动分配释放，存放函数参数、局部变量、返回地址及栈帧上下文，地址由高向低向下增长（↓）。
    • 内核空间（Kernel Space）：位于虚拟地址最高端（如 32 位 Linux 的高 1GB 0xC0000000 ~ 0xFFFFFFFF），所有进程共享同一份内核页表映射，用户态代码直接访问会触发 SIGSEGV 段错误。
  2. 程序的链接、装入与地址重定位
    • 静态重定位：在程序装入内存时一次性将所有逻辑地址加上起始物理地址修改为绝对物理地址（装入后运行期间不能移动内存位置，也无法动态扩充）。
    • 动态运行时重定位（现代 OS 标准）：装入内存时不修改逻辑地址，而是在 CPU 每次访存执行的瞬间，由硬件 MMU（内存管理单元）自动将逻辑地址加上重定位寄存器（基址寄存器）的值转换为物理地址（允许程序在内存中移动和离散分配）。
  3. 连续分配管理方式与内部 / 外部碎片
    • 内部碎片 vs 外部碎片（必考概念辨析）：
      • 内部碎片：已经分配给某个进程使用、但该进程实际用不完而闲置浪费的那部分内存（发生在固定分区分配和页式存储管理的最后一页）。
      • 外部碎片：尚未分配给任何进程、但由于块太小而无法满足新进程申请的零散空闲内存块（发生在动态分区分配和纯段式存储管理，可通过紧凑 Compaction / 内存搬移消除）。
    • 动态分区分配的四种空闲链表检索算法对比：
      1. 首次适应（First Fit，FF，综合性能最好）：空闲分区按地址递增次序链接，从头扫描找到第 1 个大小满足的空闲块分配。优点：优先利用低地址空间，高地址保留大块空闲区；缺点：低地址端容易积累许多小外部碎片。
      2. 邻近适应（Next Fit，NF / 循环首次适应）：从上次查找结束的位置继续向后扫描。缺点：导致高地址的大空闲块也被迅速切碎。
      3. 最佳适应（Best Fit，BF）：空闲分区按容量递增排序，找满足需求的最小空闲块分配。致命缺点：每次分配后切剩的尾块都极小，是最容易产生最多微外部碎片的算法。
      4. 最坏适应（Worst Fit，WF）：空闲分区按容量递减排序，每次挑最大的空闲块切分。缺点：迅速耗尽大块连续内存，导致后续大进程无法装入。

3.2 非连续分配：分页、分段与段页式存储

  1. 基本分页存储管理（Paging）
    • 核心概念：将进程逻辑地址空间切分为固定大小（如 4KB = 2^12 B）的页（Page，编号为页号 P），将物理内存同样切分为相同大小的页框 / 物理块（Frame，编号为块号 b），通过每个进程一张的页表（Page Table）记录 页号 P → 物理块号 b 的映射。
    • 逻辑地址拆分与物理地址合成公式： 设页面大小为 L = 2^k 字节，给定十进制逻辑地址 A：
      • 页号 P = ⌊A / L⌋（在二进制逻辑地址中对应高 m - k 位，即右移 k 位）；
      • 页内偏移量 W = A % L（在二进制逻辑地址中对应低 k 位，地址转换前后低 k 位原样照搬不变）；
      • 查页表得到页号 P 对应的物理块号 b 后，物理地址 = b × L + W（或将物理块号 b 的二进制直接拼接在低 k 位页内偏移 W 的高端）。
  2. 快表（TLB）与有效访问时间（EAT）定量计算（必考）
    • 为什么要引入快表（TLB，Translation Lookaside Buffer）：在基本单级页表中，CPU 每读写一个内存变量都要访存 2 次（第 1 次访存查内存中的页表获知物理块号，第 2 次访存读写目标物理地址），导致内存访问速度直接腰斩。为此，在 CPU 内部 MMU 中增设一块基于相联存储器（按内容并行查找）的高速缓存——快表（TLB），专门缓存最近刚用过的页表项。
    • 有效访问时间（EAT，Effective Access Time）计算公式： 设查询快表耗时为 ε（如 1ns），单次访问主存耗时为 t（如 100ns），快表命中率为 a（如 98%）：
      1. 顺序查找（先查快表，未命中再查慢表，标准默认情况）： EAT = a × (ε + t) + (1 - a) × (ε + 2t) = ε + (2 - a) × t
      2. 并行查找（快表与内存慢表同时启动查询）： EAT = a × (ε + t) + (1 - a) × 2t
  3. 为什么要引入多级页表（Multi-Level Page Table）
    • 单级页表的两大痛点（以 32 位系统、页面大小 4KB = 2^12 B、每个页表项 4B 为例）：
      1. 整个虚拟地址空间共有 2^32 / 2^12 = 2^20（1M）个页表项，单张页表总大小高达 2^20 × 4B = 4MB，且要求为每个进程分配连续的 4MB 物理内存（1024 个连续物理页框）；
      2. 根据局部性原理，进程在一段时间内仅使用极少量的页面，让整张 4MB 的页表全部常驻内存是巨大的浪费。
    • 多级页表的设计准则：
      • 将庞大的单级页表再次分页（使每一级子页表的大小恰好不超过 1 个物理页面 4KB，即每张页表最多含 4KB / 4B = 1024 = 2^10 个页表项，因此每一级页表索引占 10 位）；
      • 32 位逻辑地址被拆分为 10 位一级页目录号 + 10 位二级页表号 + 12 位页内偏移（64 位 Linux 采用四级或五级页表：9 + 9 + 9 + 9 + 12 = 48 位）；
      • 核心收益：进程只需将 4KB 的顶级页目录常驻内存，其余未使用的二级页表根本无需分配物理空间，需要时再按需创建或从磁盘调入。

  1. 分段管理、分页管理与段页式管理对比

3.3 虚拟内存、缺页中断与写时复制（COW）

  1. 虚拟存储器的基础：局部性原理（Principle of Locality）
    • 时间局部性：如果程序中的某条指令一旦执行，则不久以后该指令很有可能再次执行；如果某数据被访问过，则不久以后该数据很可能再次被访问（根源：程序中存在大量的循环结构）。
    • 空间局部性：一旦程序访问了某个存储单元，在不久之后，其附近的存储单元也将被访问（根源：指令顺序存放执行、数组连续存放遍历）。
    • 虚拟内存的三大特征：多次性（分多次调入内存）、对换性（运行期间换入换出）、虚拟性（逻辑容量远大于实际物理内存容量；其最大逻辑容量由 CPU 寻址位数决定，实际有效容量由“内存 + 外存交换区容量之和”与 CPU 寻址范围的较小者决定）。
  2. 请求页表与缺页中断（Page Fault）处理闭环
    • 请求页表新增的四个关键字段：
      1. 状态位 P（有效位 / 存在位）：P = 1 表示该页已在物理内存中；P = 0 表示不在内存，访问时触发缺页中断。
      2. 访问字段 A（引用位）：记录该页在一段时间内是否被访问过（供 CLOCK / LRU 等置换算法使用）。
      3. 修改位 M（脏位，Dirty Bit）：记录该页调入内存后是否被写入修改过。若被淘汰时 M == 1（脏页），必须先写回磁盘对换区；若 M == 0（干净页），则直接丢弃覆盖，无需磁盘写 I/O。
      4. 外存地址：记录该页在磁盘对换区上的物理块位置。
    • 缺页中断与一般外中断的两大本质区别：
      1. 缺页中断是在指令执行期间（属于内中断中的故障 Fault）产生并处理的，而一般外中断是在一条指令执行完毕后才检查响应；
      2. 一条指令在执行期间可能产生多次缺页中断（例如一条双操作数拷贝指令 MOV [addr1], [addr2]，指令本身跨 2 个页面，源操作数和目的操作数又各自跨 2 个页面，最多可在同一条指令中连续触发 6 次缺页中断）；且缺页修复返回后，重新执行的是刚才引发缺页的那条指令本身。

  1. fork() 写时复制（Copy-on-Write，COW）底层机制
    • 痛点：在传统 UNIX 中，fork() 创建子进程如果立即将父进程几百 MB 的物理内存页全量复制一份，既极其耗时，而且子进程往往紧接着就调用 exec() 加载新程序把刚复制的内存全部丢弃。
    • COW 两阶段硬件级协作原理：
      1. fork() 调用瞬间：内核只为子进程创建 PCB 并复制父进程的页表结构（不分配也不复制任何新的物理内存页），让父子进程的页表项同时指向相同的物理页框（物理页引用计数加 1），同时将父子双方页表项中所有可写页面的权限位统一降级修改为“只读（Read-Only）”。
      2. 写入触发缺页拷贝：当父进程或子进程中的任何一方试图向某个共享页面执行写操作时，CPU 的 MMU 检测到向“只读页”写入，立即触发页保护缺页异常（Page Fault）陷入内核；内核识别出这是 COW 页面后，才真正分配一个新的物理页框并将原页内容拷贝过去，让写入方的页表项指向新物理页（原物理页引用计数减 1），最后将双方页表项恢复为可读写（R/W）并重新执行写指令。

3.4 页面置换算法与抖动（Thrashing）

  1. 四大核心页面置换算法对比

置换算法 淘汰选择规则 性能特征与 Belady 异常
1. 最佳置换算法 (OPT) 向后看：淘汰在未来最长时间内不再被访问的页面 缺页率最低，是衡量其他算法的理论上限基准；但因无法预知进程未来访问序列，工程上无法实现
2. 先进先出算法 (FIFO) 淘汰最早进入内存（在内存中驻留时间最长）的页面 实现最简单（队列）；但早期调入的页面可能是高频使用的核心全局变量，故性能极差；是唯一会产生 Belady 异常（分配的物理块数增多，缺页次数反而升高，如序列 1,2,3,4,1,2,5,1,2,3,4,5 在 3 块时缺页 9 次、4 块时反升至 10 次）的算法
3. 最近最久未使用 (LRU) 向前看：淘汰距离当前时刻最久没有被访问过的页面 基于局部性原理，性能最接近 OPT，属于堆栈类算法（绝不会出现 Belady 异常）；但精确实现需硬件寄存器移位或哈希双向链表，开销较大
4. 时钟置换算法 (CLOCK) 将内存页排成循环队列，指针扫描访问位 A：遇 A == 1 则清零 A = 0 给第二次机会并跳过；遇 A == 0 则直接淘汰该页 性能接近 LRU 且硬件开销极小（仅需 1 bit 访问位），是现代操作系统最常用的近似 LRU 方案
  1. 改进型 CLOCK 置换算法的四轮扫描优先级（必考） 同时结合访问位 A 和修改位（脏位）M 构成二元组 (A, M)，遵循“优先淘汰未访问页，同为未访问时优先淘汰未修改的干净页（以省去磁盘写回 I/O）”的原则，最多执行四轮循环扫描：
    1. 第 1 轮扫描：寻找 (A = 0, M = 0)（最近未访问、且未修改的最佳淘汰页）。注意：第 1 轮扫描途经各页时，绝不修改访问位 A。
    2. 第 2 轮扫描：若第 1 轮未找到，寻找 (A = 0, M = 1)（最近未访问、但已修改的次佳页）。注意：第 2 轮扫描过程中，将所有途经且未选中的页面（即 A == 1 的页面）的访问位全部置为 A = 0。
    3. 第 3 轮扫描：若第 2 轮仍未找到（说明初始所有页的 A 全为 1，此时经过第 2 轮清零后，A 已全部变为 0），再次寻找 (A = 0, M = 0)（即初始为 (1, 0) 的干净页）。
    4. 第 4 轮扫描：若第 3 轮仍未找到（说明所有页初始均为 (1, 1)），寻找 (A = 0, M = 1)，本轮必定命中第 1 个页面。
  2. 驻留集、工作集与抖动（Thrashing）
    • 驻留集（Resident Set）：操作系统实际分配给某个进程的物理页框集合。
    • 工作集（Working Set W(t, Δ)）：在某段时间间隔（工作集窗口尺寸 Δ）内，进程实际访问过的不重复逻辑页面集合（去重后的页面个数即为工作集大小）。
    • 抖动（颠簸，Thrashing）：刚被换出的页面马上又要被访问，刚换入又要把别的常用页换出，导致系统把绝大部分时间都花在频繁的磁盘页面换入换出 I/O 上，而 CPU 利用率反而急剧暴跌的现象。
    • 产生抖动的根本原因与防止铁律：分配给进程的驻留集大小小于该进程当前的工作集大小（内存中同时运行的进程太多，每个进程分到的物理页框太少，无法装下其高频活跃页面）。因此操作系统必须动态监测工作集，保证 驻留集大小 ≥ 工作集大小。

第四章 文件系统

4.1 目录、FCB 与索引节点（inode）

  1. 文件控制块（FCB）与索引节点（inode）分离设计原理
    • 传统 FCB 的缺陷：文件控制块（FCB）包含文件名、权限、拥有者、文件大小、时间戳以及物理盘块地址表等全部元数据（如占 64B）。在查找目录文件时，系统其实只需要比对“文件名”字段，其余 50 多字节属性在检索过程中完全用不上，但却占用了大量目录盘块空间，导致检索大目录需要频繁读盘 I/O。
    • Unix/Linux 的“目录项 + inode”分离机制（必考计算）：
      • 目录项（dentry）仅保留两项：[文件名 + 索引节点号 inode_no]（体积缩小至 8B～16B）；
      • 索引节点（inode）：存放除文件名以外的所有文件元信息（权限、大小、硬链接计数 count、数据盘块地址指针），集中存放在磁盘的 inode 区。
      • 性能收益：假设磁盘块大小为 4KB，传统 64B 的 FCB 每块只能存 64 个文件；拆分后 16B 的目录项每块可存 256 个文件，遍历目录所需的平均磁盘 I/O 次数直接减少为原来的 1/4。
  2. 硬链接（Hard Link）与软链接（符号链接，Symbolic Link）对比

对比维度 硬链接（ln src dst · 共享同一 inode） 软链接（ln -s src dst · 独立 inode）
底层实现本质 在目录中新增一条目录项，直接指向原文件相同的 inode 编号，并使该 inode 中的硬链接引用计数 count++ 创建一个全新的独立文件（拥有新的独立 inode 号），其数据块中仅存储指向目标文件的路径字符串（类似 Windows 快捷方式）
删除原文件的影响 删除任意一个文件名仅使 count--；只要 count > 0，文件数据块就不会被回收，仍可通过其余硬链接正常读写 删除原文件后，软链接的目标路径找不到，软链接立即变成死链接（悬空失效）
跨分区与目录限制 严禁跨文件系统（跨分区）建立（因为不同文件系统的 inode 编号空间各自独立）；严禁普通用户对目录建立硬链接（防止目录树出现环路导致遍历死循环） 支持跨文件系统建立，也支持对目录建立软链接
  1. 两级打开文件表（系统级 vs 进程级）
    • open() 打开文件的目的：将指定文件的磁盘 inode 提前调入内存，避免每次 read/write 都重新从根目录按路径名检索磁盘。
    • 进程级打开文件表：每个进程一张（数组下标即为返回给用户态的文件描述符 fd，如 0: stdin, 1: stdout, 2: stderr），记录该进程当前的读写偏移指针 f_pos、访问权限及指向系统表的指针。
    • 系统级打开文件表：整个操作系统全局一张，记录内存 inode 副本及打开引用计数 open_count。调用 close(fd) 时仅使 open_count--，只有当 open_count == 0 时才将内存 inode 写回磁盘并释放表项。

4.2 文件物理分配与 Unix 多级混合索引

  1. 三种文件物理分配方式对比
物理分配方式 磁盘块组织结构 顺序 / 随机访问能力与优缺点
1. 连续分配 在磁盘上分配一组物理编号连续的盘块；目录项记录 [起始块号 + 长度] 顺序访问与直接随机访问速度最快（磁头寻道最少）；缺点：产生严重外部磁盘碎片，且文件动态增长极其困难
2. 隐式链接分配 每个数据盘块末尾留出一个指针指向下一个盘块；目录项存 [首块号 + 尾块号] 无外部碎片、文件扩展容易；缺点：仅支持顺序访问，不支持随机访问（访问第 i 块必须依次读盘 i 次），且某块指针损坏会导致后续全丢
3. 显式链接分配 (FAT) 将所有盘块的下一块指针全部抽出来集中存放在一张文件分配表（FAT）中，FAT 表开机即常驻内存 既消除了外部碎片，又因为在内存 FAT 表中查链无需读盘，故支持极快的随机访问；缺点是 FAT 表本身占用较大内存空间
  1. 索引分配与 Unix/Linux 多级混合索引（必考定量计算）
    • 为每个文件分配一个索引块（或存放于 inode 中），专门记录该文件各个逻辑块对应的物理盘块号，既无外部碎片、又完美支持随机访问。
    • 为了兼顾“小文件快速直接访问（少读盘）”与“超大文件容量上限”，Unix/Linux 在 inode 中采用多级混合索引结构： 设磁盘块大小为 B（如 4KB = 2^12 B），每个盘块号地址指针占 d 字节（如 4B），则每个索引块可容纳的盘块号个数为 k = B / d = 4KB / 4B = 1024 = 2^10：
      1. n 个直接地址项（如 n = 12）：直接指向数据盘块，无需读索引块。可表示容量 = n × B（12 × 4KB = 48KB）；
      2. 1 个一次间接地址项：指向一个一级索引块，包含 k 个数据块指针。可表示容量 = k × B（1024 × 4KB = 4MB）；
      3. 1 个二次间接地址项：指向二级索引块，可寻址 k^2 个数据块。可表示容量 = k^2 × B（1024^2 × 4KB = 4GB）；
      4. 1 个三次间接地址项：指向三级索引块，可寻址 k^3 个数据块。可表示容量 = k^3 × B（1024^3 × 4KB = 4TB）；
      • 最大文件总长度公式：MaxSize = (n + k + k^2 + k^3) × B。
      • 随机访问某个偏移位置所需的读盘次数（假设 inode 已在内存）：落在直接块需 1 次 I/O（直接读数据块）；落在一次间址需 2 次 I/O（1 次读一级索引块 + 1 次读数据块）；落在二次间址需 3 次 I/O；落在三次间址需 4 次 I/O。

4.3 空闲磁盘空间管理

  1. 空闲表法与空闲链表法
    • 空闲表法：为所有连续空闲盘块区建立一张表（记录第一块号与空闲块数），采用首次适应或最佳适应分配（适合连续分配）。
    • 空闲盘块链 / 空闲盘区链：将空闲盘块或空闲盘区串联成链表。
  2. 位示图法（BitMap，现代文件系统标准，必考换算公式）
    • 利用二进制的一位（1 bit）表示磁盘中一个物理盘块的使用状态（0 表示空闲，1 表示已分配），所有位排成二维矩阵（每行对应一个机器字，设字长为 n 位，如 n = 32 或 64）：
    • 0-based 下标换算公式（行号 i、列/位号 j、物理盘块号 b 均从 0 开始编号）：
      • 已知 (i, j) 求盘块号：b = n × i + j
      • 已知盘块号 b 求行列号：i = ⌊b / n⌋ ， j = b % n
    • 1-based 下标换算公式（若题目明确规定行号 i、位号 j、盘块号 b 均从 1 开始编号）：
      • 已知 (i, j) 求盘块号：b = n × (i - 1) + j
      • 已知盘块号 b 求行列号：i = ⌊(b - 1) / n⌋ + 1 ， j = (b - 1) % n + 1
  3. 成组链接法（UNIX 系统采用）
    • 将空闲盘块分成若干组（如每组 100 块），把下一组的所有空闲盘块号及块数记录在前一组的第 1 个盘块（组长块）中，仅将第一组的信息常驻内存超级块（Superblock）中，兼顾了大磁盘下内存占用小与批量分配释放的高效率。

第五章 输入/输出（I/O）与磁盘管理

5.1 四种 I/O 控制方式、I/O 多路复用与零拷贝

  1. 四种 I/O 控制方式的演进对比
I/O 控制方式 CPU 干预时机与频率 每次数据传输单位与数据流向 核心特征与适用场景
1. 程序直接控制
(轮询 Polling)		 CPU 全程死循环不断轮询检查设备状态寄存器 1 个字（或字节）
设备 → CPU 寄存器 → 内存		 CPU 与外设完全串行工作，CPU 利用率极低
2. 中断驱动方式
(Interrupt-Driven)		 每读写完 1 个字/字节，设备控制器向 CPU 发出 1 次中断 1 个字（或字节）
设备 → CPU 寄存器 → 内存		 实现了 CPU 与外设并行，但高速大批量传输时每字中断一次会淹没 CPU（适合键盘、鼠标等低速字符设备）
3. DMA 方式
(直接内存访问)		 仅在整块（如 4KB）数据传输开始前和全部结束后才干预 1 次 数据块（Block）
设备 ↔ 内存（直接通过总线，不经 CPU）		 由 DMA 控制器窃取总线周期直接将数据写入内存，大幅解放 CPU（适合磁盘、网卡等高速块设备）
4. 通道控制方式
(I/O Channel)		 完成一组离散的多个数据块读写后才向 CPU 发出 1 次中断 一组数据块 通道是拥有独立通道指令的“弱化版专用 CPU”，CPU 干预频率最低

  1. 网络 I/O 多路复用：select / poll vs epoll
    • 为什么需要 I/O 多路复用：让单个线程能够同时监听成千上万个网络连接套接字（fd）的可读/可写事件，避免为每个连接创建一个线程带来的内存与上下文切换爆炸。
    • select 与 poll 的三大性能瓶颈：
      1. 每次调用都必须将整个监听 fd 集合从用户态全量拷贝到内核态（select 默认上限仅 1024 个）；
      2. 内核收到网络包后，不知道具体哪个 fd 就绪，必须 O(n) 线性遍历全量 fd 集合；
      3. 返回用户态后，用户程序仍需 O(n) 遍历整个集合找出就绪的 fd。
    • Linux epoll 的三大底层突破（epoll_create / epoll_ctl / epoll_wait）：
      1. 红黑树常驻内核：在内核空间维护一棵红黑树存储所有待监听的 fd，通过 epoll_ctl 增删改查的时间复杂度仅为 O(log2 n)，无需每次重复拷入全集；
      2. 中断回调 + 就绪双向链表 rdlist：注册 fd 时向内核网卡驱动挂载回调函数 ep_poll_callback；当某个 socket 收到数据时，网卡中断直接调用回调将该 fd 挂入就绪双向链表，epoll_wait 只需 O(1) 检查就绪链表是否非空并仅拷回已就绪的活跃 fd（时间复杂度与总连接数无关，仅与活跃连接数相关）；
      3. 两种事件触发模式：
        • 水平触发（LT，Level-Triggered，默认）：只要 socket 接收缓冲区中还有未读完的数据，epoll_wait 每次都会重复返回通知；
        • 边缘触发（ET，Edge-Triggered，高性能）：仅在 socket 状态从“无数据”变为“有数据”的瞬间通知 1 次，必须配合非阻塞 I/O（Non-blocking）循环读到返回 EAGAIN 为止。
  2. 零拷贝（Zero-Copy）技术
    • 传统文件网络发送（read(file) + write(socket)）的开销：数据经历 磁盘 →(DMA)→ 内核 PageCache →(CPU)→ 用户态缓冲区 →(CPU)→ 内核 Socket 缓冲区 →(DMA)→ 网卡，共计 4 次用户态/内核态上下文切换 + 4 次数据拷贝（含 2 次消耗 CPU 的内存拷贝）。
    • sendfile + SG-DMA（收集 DMA）零拷贝：通过单次系统调用 sendfile()，直接在内核态将 PageCache 的内存地址与长度描述符传递给 Socket 缓冲区，再由网卡 SG-DMA 直接从 PageCache 读取数据发往网络——降为 2 次上下文切换 + 2 次 DMA 拷贝（全程 0 次 CPU 内存拷贝）。

5.2 I/O 软件层次、SPOOLing 与缓冲区定量计算

  1. I/O 软件的四层架构与假脱机技术（SPOOLing）
    • I/O 软件四层（自顶向下）：用户层 I/O 软件（提供库函数与 SPOOLing）→ 设备独立性软件（设备无关层）（统一命名、逻辑设备名到物理设备名映射 LUT、权限保护、缓冲区管理）→ 设备驱动程序（将抽象请求翻译为具体控制器寄存器指令）→ 中断处理程序（直接与硬件交互）。
    • SPOOLing（假脱机技术）：利用高速磁盘上的输入井和输出井模拟慢速字符外设，在内存中运行预输入程序和缓输出程序，将一台物理上独占的慢速设备（如打印机）改造为多台逻辑上的共享虚拟设备（以空间换时间）。
  2. 单缓冲与双缓冲每块数据平均处理时间计算（408 必考公式） 设外设将一块数据输入到内核缓冲区耗时为 T，操作系统将数据从内核缓冲区传送（拷贝）到用户进程工作区耗时为 M，CPU 对工作区数据进行计算处理耗时为 C：
    • 单缓冲（Single Buffering，缓冲区被占用时外设与搬移串行，CPU 计算 C 可与下一块的输入 T 并行）： 处理每块数据的平均耗时为： T_单缓冲 = max(C, T) + M
    • 双缓冲（Double Buffering，外设往缓冲 1 输入 T 的同时，可并行将缓冲 2 的数据传送 M 并由 CPU 计算 C）： 处理每块数据的平均耗时为： T_双缓冲 = max(C + M, T)

5.3 磁盘结构、访问时间与磁臂调度算法

  1. 磁盘物理结构与单次读写访问时间三要素公式
    • 盘面（Head）、磁道（Track，同心圆）、柱面（Cylinder，所有盘面上相同半径的磁道集合）与扇区（Sector，磁盘最小物理读写单位，通常 512B 或 4KB）：磁盘物理地址表示为 (柱面号, 盘面/磁头号, 扇区号)（注意柱面号在最前、盘面号居中，这样连续读写大文件时优先在同一柱面内电子切换磁头，无需机械移动磁臂寻道）。
    • 单次磁盘读写总时间 Ta 由三部分相加组成（必背公式）：
      1. 寻道时间 Ts（耗时占比最大，约数毫秒）：将磁头臂径向移动到目标磁道（柱面）所需时间：Ts = m × n + s（跨越 n 条磁道 + 启动磁臂常数耗时 s）；
      2. 平均旋转延迟时间 Tr：等待目标扇区旋转到磁头正下方的时间，平均按旋转半圈（1/2 周）计算。设磁盘转速为 r（注意把题目中的 RPM 每分钟转数 除以 60 换算为每秒转数 r）： Tr = 1 / (2r)
      3. 传输时间 Tt：磁头扫过扇区读写字节的时间。设单条磁道总容量为 N 字节，本次读写 b 字节： Tt = b / (r × N)
  2. 四大磁盘磁臂调度算法对比（寻道距离计算）

磁盘调度算法 磁头移动规则 性能特征与饥饿辨析
1. 先来先服务 (FCFS) 严格按进程请求访问磁道的先后次序寻道 公平简单、无饥饿；但磁头大幅度来回折返，平均寻道距离最长
2. 最短寻道时间优先 (SSTF) 贪心选择距离当前磁头所在位置最近的请求磁道优先访问 平均寻道时间最短；但如果磁头附近持续有新请求到达，会导致远端边缘磁道请求无限期“饥饿”（唯一会饥饿的磁盘调度算法）
3. 扫描算法 (SCAN / 电梯算法) 与 LOOK 磁头沿当前移动方向依次服务沿途所有请求，直到边缘（或最远请求）再掉头反向扫描 兼顾寻道效率与公平性，彻底消除了饥饿现象。
注意考试默认规则：若题目未特别说明是传统 SCAN（必撞磁盘物理边界 0 或 MAX），408 中常说的 SCAN 默认指 LOOK 算法（只需移动到该方向上的最远请求磁道即立刻掉头折返）
4. 循环扫描 (C-SCAN) 与 C-LOOK 规定磁头只在单向移动时提供服务，到达最远端后立即快速空移返回起始端重新同向扫描 消除了 SCAN 掉头时对两端磁道请求响应的不对称性。
同理，C-LOOK 到达该方向最大请求磁道后，直接跳回最小请求磁道继续单向扫描（注意空移折返的那一段距离也必须计入磁头移动总道数）
