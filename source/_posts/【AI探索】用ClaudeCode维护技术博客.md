## 重新打开这个博客

2026 年 7 月，我决定重新维护这个荒废了一年多的 Hexo 博客。手头有一批旧技术笔记，仓库也有分支、配置和部署问题要处理。我让 Claude Code 协助盘点和执行，自己负责选内容、定公开边界，以及确认会影响仓库历史的操作。

## 先找到真正的源文件

一开始打开的是 `main` 分支：里面只有生成后的 HTML，没有 `_config.yml` 和 `source/`，不能直接用来继续写博客。检查远程分支后，才找到真正的 Hexo 源码分支 `source`；`gh-pages` 则保存部署产物。

仓库里的 `.cursor/rules` 记录了文章目录、分类和 front matter 规范。让工具先读这些现成约定，比边做边猜更省事。

当时 `main` 还是默认分支。Claude Code 提醒我，不能直接删默认分支：要先将默认分支切换到 `source`，再清理旧分支。涉及分支删除和历史变更时，我先确认目标和影响，再执行。

## 整理旧笔记，也清理历史里的个人信息

我整理了一份 2000 多行的旧笔记，里面混有面试记录、个人经历和 C++、Unity 等技术内容。Claude Code 先和我核对哪些主题已经写过，最后只把博客缺少的内容整理成文，例如排序算法、图与搜索、计算机基础、UGUI 源码和 GC 原理。

整理正文时，我删掉了真实姓名、雇主信息和面试话术。但检查 Git 历史后发现，部分公司名称还留在旧版本和 commit message 里。只改当前文件并不能清除这些记录，于是我用 `git filter-repo --replace-text` 重写相关历史，再强推更新远端。**脱敏要检查的不只是当前文件，也包括版本历史。**

## 顺手修复几个影响使用的问题

- 更新 About 页面和 GitHub profile README，描述工作方向时不公开具体雇主。
- README 里的 GitHub Stats 图片持续返回 503。检查后确认是公共服务实例不可用，于是换成当时能访问的统计图源。
- 修正精选项目中拼错的仓库用户名，避免链接跳到 404 页面。

这些工作单项不大，但分散在不同文件和服务里。先定位原因再改，比盲目替换更重要。

## 把重复步骤交给脚本

每次发布都要生成封面。后来我把这一步整理为本地脚本：

```bash
bash tools/covers/new-cover.sh
```

脚本为缺少 `cover:` 的文章生成封面并写回 front matter，再把 SVG 渲染为 PNG；已有的手动封面会保留。站点则由 GitHub Actions 构建部署。封面生成规则和当前图解样式另写在《自动化封面生成系统》中。

## 这次协作的边界

Claude Code 最有帮助的地方，是快速梳理陌生仓库、查找问题来源，以及把重复操作整理成脚本。文章写什么、哪些个人信息可以公开，仍然要我决定；删除分支、重写 Git 历史和强推，也需要我先理解影响再确认。

对我来说，合适的分工不是把博客交给 AI，而是我确定目标和边界，让它协助调查与执行。重复流程稳定下来以后，后续维护也不必每次从头摸索。
